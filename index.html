Anynotate demo kit

Fix a recipe page with five notes.

A presenter guide for showing Anynotate live or on video. You leave notes on a small tomato soup page, send them to an AI coding agent, and the page updates in front of the audience.

Before you start

  • Chrome (or Edge, Brave, Chromium) with the Anynotate extension installed and pinned
  • anynotate install done, and anynotate doctor passes
  • git, plus bun for live reload (python3 works, but you refresh by hand)
  • An agent: Claude Code, Codex, or anything that can read a file or use MCP; optionally herdr
  • This kit cloned somewhere, for example ~/anynotate-demo-kit

Setup

The setup script clones the demo site into ~/anynotate-demo (or a folder you pass), runs anynotate doctor and starts the page at http://localhost:5173.

macOS and Linux 
git clone https://github.com/genexk/anynotate-demo-kit.git ~/anynotate-demo-kit
~/anynotate-demo-kit/scripts/setup.sh
~/anynotate-demo-kit/scripts/check.sh   # pre-flight, changes nothing
Windows (PowerShell) 
git clone https://github.com/genexk/anynotate-demo-kit.git $HOME\anynotate-demo-kit
pwsh -File $HOME\anynotate-demo-kit\scripts\setup.ps1
pwsh -File $HOME\anynotate-demo-kit\scripts\check.ps1

Setup and reset take --dry-run (-DryRun in PowerShell); every script takes an optional demo folder. ANYNOTATE_DEMO_DIR and ANYNOTATE_DEMO_PORT change the defaults.

Pick an agent

Whichever you choose, start it in the demo folder, so it can edit the page. The demo's CLAUDE.md and AGENTS.md ask for small edits and no new dependencies.

herdr pane

Best for recordings: notes are typed into the pane the moment you send.

cd ~/anynotate-demo
claude      # or codex

In the dock, pick the pane labelled … · claude · anynotate-demo.

Claude Code or Codex session

Outside herdr. The session shows with ⏳: notes arrive with your next message.

cd ~/anynotate-demo
claude

Send from the dock, then type go in the session.

Inbox, for any agent

Pick 📥 Inbox in the dock, then ask the agent to read the notes:

  • /annotations in Claude Code or Codex
  • “Read my browser notes” over MCP (anynotate mcp install)
  • or point it at ~/.anynotate/inbox/latest/README.md

The five notes

Each one is a small, real problem on the page: easy to miss, obvious once someone points at it. Turn notes on with Alt+Shift+A. To pick an element, use the crosshair or Alt+Shift+E.

  1. The pale Save button

    ElementRequest change
    Point at
    The orange Save recipe button at the bottom.
    Type
    This button is hard to read. Give it enough contrast to pass WCAG AA, and keep it orange.
    Expect
    The agent darkens the button colour in site/style.css; the button turns a deep burnt orange with readable white text.
    Say
    “I point at the button and say what’s wrong in plain words. No selectors, no screenshots pasted into a chat.”

  2. 25 or 45 minutes?

    Text selectionExplain
    Point at
    Select about 25 minutes in the line under the picture. The badge at the top says 45 minutes.
    Type
    The badge at the top says 45 minutes. Which one is right? Add up the steps and make the two agree.
    Expect
    The agent adds up the method (10 + 25 + 10 = 45 minutes), says the badge is right, and changes the line to “about 45 minutes”.
    Say
    “Notes aren’t only change requests. I can ask about any sentence, and the agent gets the exact words I selected.”

  3. The cramped ingredients

    ElementRequest change
    Point at
    The whole Ingredients list (pick the list, not one line).
    Type
    These lines are cramped. Give the list more breathing room, like the method steps below.
    Expect
    The agent raises the line height and adds space between items in site/style.css.
    Say
    “Each note carries the element, its styles and a crop, so ‘cramped’ is all I need to say.”

  4. Servings that don’t scale

    ElementRequest change
    Point at
    Click 6 under Servings first, so the audience sees the badge change and the amounts stay put. Then pick the servings buttons.
    Type
    Picking 2 or 6 changes the badge, but the ingredient amounts stay the same. Make them scale.
    Expect
    The agent finds that site/app.js looks for amounts the markup never marks, and fixes it. Picking 6 now shows 1.5 kg tomatoes and 1125 ml stock.
    Say
    “My note is about what I see. The agent goes from the button to the bug in the JavaScript.”

  5. A paler-than-ripe tomato

    RegionRequest change
    Point at
    Drag a region around the big tomato in the middle of the picture.
    Type
    Make this tomato a deeper, riper red.
    Expect
    The agent changes the big tomato’s fill in the picture in site/index.html; the cherry tomatoes stay as they are.
    Say
    “I can circle part of a picture, and the agent edits the right shape.”

Run of show

Short take, about 90 seconds

Notes 1, 4 and 5, one send. Shows an element, a bug behind the UI and a region.

Full take, 3 to 4 minutes

All five, then one send with an overall note:

Five small fixes on the recipe page. Keep each change minimal.

One at a time

Send after each note and let the page reload before the next. Slower, but each change lands on its own.

Recording tips

  • Browser window 1280 × 800, page zoom 100% (⌘/Ctrl+0)
  • Hide the bookmarks bar (⌘+Shift+B, or Ctrl+Shift+B); use a clean profile with only Anynotate pinned
  • Agent terminal beside the browser, font size 16 or more; turn on Do Not Disturb
  • Run check.sh right before each take, and reset.sh right after
  • Type the notes yourself on camera, or paste them with the Copy buttons above if you are short on time
  • Pause a beat after each send: the page reloads by itself, and that moment is the demo

Reset between takes

~/anynotate-demo-kit/scripts/reset.sh --dry-run   # see what it would do
~/anynotate-demo-kit/scripts/reset.sh

Reset only works on the demo clone: it checks for the committed .anynotate-demo marker and an origin of genexk/anynotate-demo (or a local anynotate-demo folder), and stops if either is missing. Then it:

  1. stops the demo server it started (never another process on the port),
  2. runs git reset --hard origin/main and git clean -fd in the demo clone,
  3. starts the server again; an open page reloads itself,
  4. removes Anynotate bundles whose page URL starts with http://localhost:5173 from ~/.anynotate/inbox and archive (or $ANYNOTATE_HOME). Notes from every other page stay.

One thing the scripts can’t do: saved but unsent notes live in the browser. Open Anynotate’s Options and click Clear all unsent notes, or delete the notes for this page in the dock.

Troubleshooting

The page doesn’t change after the agent edits it

Live reload needs bun. With the python3 fallback, refresh by hand. Check ~/anynotate-demo/.serve.log for errors.

Port 5173 is already taken

Set ANYNOTATE_DEMO_PORT=5174 for setup, check and reset alike. Reset then cleans notes for http://localhost:5174 only.

My agent isn’t in the dock’s Sessions list

Start it in the demo folder and press refresh in the dock. anynotate status lists what the bridge sees. The 📥 Inbox always works.

The extension says it can’t reach the bridge

Run anynotate doctor; re-running anynotate install restarts the bridge.

Reset says the folder is not a clone of anynotate-demo

That’s the safety check. Pass the demo folder: reset.sh ~/anynotate-demo.

Old notes still show on the page after a reset

They are unsent notes kept by the browser: Options → Clear all unsent notes.

The agent changed more than I asked

Reset and take it again. If it keeps happening, add the overall note “Keep each change minimal.”

PowerShell won’t run the scripts

Run them with pwsh -ExecutionPolicy Bypass -File scripts\reset.ps1.
